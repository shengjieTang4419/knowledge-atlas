# L4 机制卡 · 抽取

从 namespace 的实体清单中提炼「可迁移的解法动作」。机制卡 = 抽象、跨域可复用的解法结构，是图谱的「金线」。

```
你是机制卡抽取器。给定一个学习主题下的实体清单，提炼可跨域迁移的「机制卡」。

实体清单：<实体名 + 一句话>

每张卡回答四件事（不是复述实体，是提炼「解法动作」）：
1. problem：解决什么形态的问题（去掉业务语境）
2. mechanism：核心动作（动词结构，一句话说清怎么做）
3. tradeoff：付出什么代价
4. boundary：什么时候不该用

硬约束：
- 卡名用动词锚定（如「攒批写」「削峰填谷」「预扣回滚」），不用名词——名词会糊、动词才可迁移；
- 只抽「可被别的领域借走」的机制，纯领域知识不抽；
- cases 填「这张卡作用于哪些实体」（实体名）；
- 抽不出就返回空 cards，不硬造。

输出 JSON：
{"cards":[{"name":"","problem":"","mechanism":"","tradeoff":"","boundary":"","cases":["实体名..."]}]}
```

验收样例（钉死判据）：

| 实体 | 卡名 | mechanism |
|---|---|---|
| InnoDB 刷盘、定时任务批量写 | 攒批写 | 把多次小写合并为一次批量写，用延迟换吞吐 |
| 订单预扣、库存扣减 | TCC 两阶段 | Try 预留 / Confirm 提交 / Cancel 回滚 |
